F-020 · Design Approval Package · revisão 1

Jornada web do orçamento-base

Este caderno é artefato de aprovação, não implementação. Ele existe para que a discordância sobre o desenho aconteça agora, enquanto descartar é barato. Cada tela abaixo aparece dentro de uma moldura: dentro da moldura é produto, fora dela é comentário meu.

O que está desenhado aqui é proposta de agente, exceto onde diz “espelho”: aí é a linguagem que a jornada de medição já estabeleceu e que este pacote apenas reutiliza. Cor e tipografia citam o docs/engineering/DESIGN_SYSTEM.md lido em 2026-08-19; tamanho, espaçamento e raio são valores novos, porque o projeto não tem escala para nenhum dos três.

Dados de todas as telas são sintéticos e ilustrativos — nomes, códigos, quantidades e preços não são especificação.

Tela 2 — Cascata de catálogos

Não existe equivalente na medição, e é o que separa os dois momentos: lá o catálogo é um só e imutável na rodada; aqui são várias fontes numa ordem que a orçamentista declara. A ordem é a regra de precificação — o primeiro catálogo que tiver o código é o que precifica —, então ela precisa ser visível, numerada e reordenável, nunca implícita.

Cascata de fontes de preço

A ordem manda: para cada item, vale o preço da primeira fonte que tiver o código. Uma origem não se repete na cascata.

Tela 6 — BDI e montagem do orçamento

Conceito que não existe em nenhuma linha do produto hoje e nasce aqui. Decisão sua desta sessão: percentual único por orçamento agora, com o BDI por grupo desenhado apenas como espaço reservado — visualmente distinguido e inerte, não um controle que não faz nada.

BDI

O preço unitário com BDI é truncado em centavo, linha a linha, como todo dinheiro deste módulo — e o total sai do preço com BDI.

Reservado — não entra nesta feature

BDI por grupo

Percentuais distintos para serviços e para equipamentos/fornecimento, como a prática admite.

Vira real quando o item carregar grupo como dado e houver decisão humana registrada em ADR. Até lá não é renderizado no produto — aparece neste caderno para segurar o lugar, não para ser um controle desligado.

Recusa de domínio, traduzida por tabela

Este item cita um catálogo que não está na cascata deste orçamento. Instale a fonte ou escolha um código de uma das fontes instaladas.

ESTIMATE_LINE_SOURCE_UNKNOWN

O código escolhido não tem o formato da fonte de onde ele diz vir.

ESTIMATE_CODE_INVALID_FOR_ORIGIN

Toda mensagem sai de tabela, como na medição: o código da invariante vem do servidor e a frase é escrita aqui. Nenhuma mensagem é inventada em tempo de execução, e o código fica visível para o suporte.

O que este mock não decide

  • Qual papel autoriza a jornada. Reusar o papel da medição (orcamentista) ou criar um próprio para pré-licitação é decisão sua, ainda aberta. O 403 aqui é genérico por causa disso.
  • Como o escritor de planilha passa a aceitar o orçamento. Adaptador ou generalização do escritor é decisão técnica do plano, não deste artefato — o que se aprova aqui é o layout impresso.
  • A forma do auditor. Reusar o auditor da medição ou escrever um próprio fica para o plano; o que este pacote fixa é que existe portão e que ele falha fechado.
  • BDI por grupo. Desenhado como reservado, com a condição escrita. Aprovar este caderno não aprova o BDI por grupo.
  • Copy final. Os textos aqui são proposta. Aprovar o visual não aprova o texto — os dois são atos separados, como foi na F-007.
  • Layout conferido contra o exemplar real. Enquanto o arquivo da prefeitura não for lido, o layout desta rendição sai do modelo do boletim que já existe em código.
